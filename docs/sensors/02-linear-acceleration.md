| Android type | `Sensor.TYPE_LINEAR_ACCELERATION`（值为 10） |
| SI 单位 | m/s² |
| 分量 | x y z + abs |
| 众包库字段 | `l` 仅有/无 |
| 接入状态 | 仅对照，未改实验 |
| 研究状态 | 待研究（依赖加速度计结论） |

## 1. 物理量与期望值

多数机没有第二颗「线性加速度芯片」。它是从硬件加速度计（常加陀螺）**合成**的：\(\mathbf{a}_\text{linear} \approx \mathbf{a} - \mathbf{g}\)。理想静止：三轴和模长都接近 0，不是 \(g\)。

若加速度计 HAL 用 g 当单位，线性加速度几乎一定同一套，静止可能看到 ~0，运动峰值却只有「应有 SI 值的 1/9.8」。

## 1.1 重力怎么消、凭什么判断

芯片消不掉重力。它只交出 \(\mathbf{a}\)。系统在中枢或 HAL 里**估计** \(\mathbf{g}\)，再减：

\[
\mathbf{a}_\text{linear} = \mathbf{a} - \hat{\mathbf{g}}
\]

常见两类（OEM 具体公式看不到）：

1. **低通**：认定重力变化慢，运动是高频。\(\hat{\mathbf{g}} \leftarrow (1-\alpha)\hat{\mathbf{g}} + \alpha\,\mathbf{a}\)，线性 = 高通残差。
2. **加陀螺**：用角速度积分更新姿态，把「竖直向下」转到机身坐标，得到 \(\hat{\mathbf{g}}\)。加速度计只在长时间尺度上把方向拉回，避免积分漂。

算法内部的判断依据（假设，不是我们设的）：

| 假设 | 含义 |
|---|---|
| \(\|\mathbf{g}\|\) 近似常数 | 地球上约 9.8（若 HAL 用 g 单位则约 1） |
| 重力相对姿态慢变 | 转得太快时估计跟不上 |
| 线性加速度时间平均 ≈ 0 | 持续加速（电梯、汽车）会被吃进 \(\hat{\mathbf{g}}\) |
| 静止时 \(\mathbf{a} \approx \mathbf{g}\) | 用这段把方向锁死 |

我们在传感器页能核对的判据（Phyerma 现只展示，不参与合成）：

| 现象 | 分离大概对 | 分离可疑 |
|---|---|---|
| 静放 | \(\|\mathbf{a}_\text{linear}\| \approx 0\)，\(\|\mathbf{g}\| \approx \|\mathbf{a}\|\) | 线性长期有零偏 |
| 矢量 | \(\mathbf{a} \approx \mathbf{a}_\text{linear}+\mathbf{g}\) | 三路对不上 |
| 平动再停下 | 线性有峰后回到 0 | 峰被吃掉或回不来 |
| 原地快转 | 线性只有小尖峰 | 很大的假加速度 |
| 自由落体 | \(\mathbf{a}\approx 0\)，线性与重力都不可信 | — |

Phyerma **不**自己消重力。实验要无重力加速度时，读的是系统的 `TYPE_LINEAR_ACCELERATION`。

## 1.2 系统拆错了能不能校准

会拆错。国产中枢滤波、滞后、把持续加速吃进重力，都常见。应用改不了中枢，只能在收到的 float 上动手，或**不用**系统的线性加速度。

| 做错的是什么 | 能不能校准 | 做法 |
|---|---|---|
| 单位（1 当 g） | 能 | 静止看硬件 \(\|\mathbf{a}\|\)，三路同乘 \(g_0\) |
| 线性零偏（静放不是 0） | 能 | 用户静放几秒，减掉均值；会漂，需可重置 |
| 轴偏 / 不正交 | 勉强 | 六面标定，课堂太重 |
| 分离滞后、假尖峰 | **不能**靠乘系数修好 | 信息已被滤错 |
| 电梯里真实加速度被吃掉 | **不能**从系统线性加速度里捞回 | 已被算进 \(\hat{\mathbf{g}}\) |

可靠的一条：实验需要「无重力加速度」时，改读硬件 `TYPE_ACCELEROMETER`（+ 可选陀螺），**应用内自己做低通/互补滤波**，开关给用户。这样滤错可以改参数，不求 OEM 重刷 HAL。

现在两件事都没做：不校正系统线性加速度，也不自己拆重力。

## 2. 代码路径

`SensorInput` → `getDefaultSensor(TYPE_LINEAR_ACCELERATION)`。无校准开关，无 vendor 回退。  
`SensorCatalog.dbBaseline` **没有**为这个 type 拼库文本（`l` 只在本机页当有无）。

## 3. 内置实验

`linear_accelerometer.phyphox`，`spring.phyphox`（50 Hz），`elevator.phyphox`（与气压一起），`centripetal_acceleration.phyphox`，`motion_stopwatch.phyphox`。

## 4. 已知坑

- 重力分离滞后：猛转手机时会短暂冒出假加速度。
- OEM 实现质量差，噪声和零偏都可能比原始加速度计差。
- 库没有 rest 均值，没法用 `aa` 直接对照。

## 5. 现行做法

实验原样。传感器页能看实时值和 2 s σ/Hz，没有库基线。

## 6. 候选规则（草案）

加速度计若确认「× \(g_0\)」，线性加速度默认同一开关，避免弹簧/电梯一边对一边错。静止模长应保持 ~0，检测应看**运动峰值**或与原始加速度计并排，不能用 rest-g。
