# GPS / 定位

| 项 | 值 |
|---|---|
| 实验类型名 | `<location>`（不是 SensorInput） |
| Android API | `LocationManager` / GNSS |
| SI 单位 | 度（经纬）、米（高程/精度）、m/s（速度） |
| 分量 | lat lon 海拔 WGS84 速度 方向 时间 水平/垂直精度 状态 卫星数 |
| 众包库字段 | 无（库不管 GNSS） |
| 接入状态 | 独立实现，未做国产机专项 |
| 研究状态 | 待研究 |

## 1. 物理量与期望值

室外空旷：水平精度数米到十几米。室内往往无解或只有网络定位。海拔是薄弱项（椭球高 vs 海拔）。

## 2. 代码路径

`GpsInput.java`。`forceGNSS` 可要求卫星定位。有 `GpsGeoid` 做大地水准面。权限与系统定位开关是前提。

## 3. 内置实验

`gps.phyphox`。列表里「定位 (GPSS)」那条原始传感器实验走的也是这套，不是 IMU。

## 4. 已知坑

- 国产机 GNSS 芯片（北斗优先等）一般可用，坑在权限、省电杀掉定位、室内 NLP。
- 不要和加速度计单位问题混为一谈。
- 高程误差常大于水平，不适合当精密高度计（高度优先气压，见 `05`）。

## 5. 现行做法

上游原样。本机页只标「定位传感器是否存在」，不做 GNSS 精度统计。

## 6. 候选规则（草案）

传感器页可加 GNSS 实时精度/卫星数，但不改经纬度。保活/权限是产品问题，另开篇。
